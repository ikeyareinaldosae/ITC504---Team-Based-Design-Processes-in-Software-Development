## 🛠️ GitHub Working Agreements

### 1. Branching & Commits
* Branch naming: `feat/[feature-name]`, `fix/[issue-name]`, or `docs/[change]`
* Use conventional commit messages (e.g., `feat: add user authentication`).

### 2. Pull Requests (PRs)
* Keep PRs small and focused (< 400 lines changed preferred).
* Every PR requires **[1 or 2]** approved reviews before merging.
* Link relevant GitHub issues in the description using keywords (e.g., `Closes #12`).

### 3. Issue Management
* Use labels for categorization (`bug`, `enhancement`, `priority: high`).
* Assign issues to yourself before starting work to avoid duplication.

---

## ⚡ Conflict Resolution
1. **Direct Discussion:** Address the issue 1-on-1 constructively.
2. **Team Level:** Bring technical disagreements to GitHub Discussions or a team sync to evaluate trade-offs objectively.
3. **Escalation:** Consult the Project/Tech Lead for a final decision if consensus cannot be reached.
